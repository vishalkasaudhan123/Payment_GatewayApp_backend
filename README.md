# Payment Gateway Backend

A Spring Boot based Payment Gateway Backend application that provides a REST API for processing payment transactions through multiple payment methods such as **UPI, Credit Card, Debit Card, and Net Banking**.

The application follows a layered, service-based architecture where the `PaymentController` handles HTTP requests and responses, while `PaymentTransactionService` coordinates payment processing and dynamically selects the appropriate payment strategy.

```http
POST /api/payments
```

### Complete URL

```text
http://localhost:8080/api/payments
```

### Content-Type

```text
application/json
```

---

## 📥 Payment Request

The API accepts a `PaymentRequest` object.

The request contains the following fields:

| Field    | Type   | Description    |
| -------- | ------ | -------------- |
| `amount` | double | Payment amount |
| `method` | String | Payment method |
| `upi`    | String | UPI details    |
| `card`   | String | Card details   |
| `cvv`    | String | Card CVV       |
| `bank`   | String | Bank details   |

Example UPI request:

```json
{
    "amount": 1500,
    "method": "upi",
    "upi": "user@upi"
}
```

Example card request:

```json
{
    "amount": 2500,
    "method": "card",
    "card": "4111111111111111",
    "cvv": "123"
}
```

Example net banking request:

```json
{
    "amount": 3000,
    "method": "netbanking",
    "bank": "Test Bank"
}
```

> Use test data while testing payment APIs. Do not use real card numbers, CVV values, or banking credentials.

# 🔄 Payment Processing Flow

```text
Client
   |
   | POST /api/payments
   v
PaymentController
   |
   | PaymentRequest
   v
PaymentTransactionService
   |
   | Validate Request
   |
   | Find Payment Method
   v
Map<String, PaymentService>
   |
   +----> UPI Payment Service
   |
   +----> Credit Card Payment Service
   |
   +----> Debit Card Payment Service
   |
   +----> Net Banking Payment Service
   |
   v
PaymentResult
   |
   +----> Success
   |       |
   |       v
   |   Success Transaction
   |
   +----> Failure
           |
           v
       Failed Transaction
```

The `PaymentTransactionService` dynamically selects the appropriate `PaymentService` implementation based on the payment method received in the request.

# 🧩 Payment Services

The backend uses separate payment service implementations for different payment methods.

### UPI Payment Service

Handles UPI payment processing.

### Credit Card Payment Service

Handles credit card payment processing.

### Debit Card Payment Service

Handles debit card payment processing.

### Net Banking Payment Service

Handles net banking payment processing.

The payment strategy is selected dynamically using the configured `PaymentService` implementations.

---

# 🗄️ Transaction Management

The application maintains separate transaction records for successful and failed payments.

### Successful Transactions

Successful payment transactions are stored using:

```text
SuccessPaymentTransactionRepository
```

### Failed Transactions

Failed payment transactions are stored using:

```text
FailedPaymentTransactionRepository
```

This allows successful and failed transactions to be maintained separately.

---

# 📊 Payment Result

The payment operation returns a `PaymentResult` containing:

```java
public record PaymentResult(
        boolean success,
        String transactionId,
        String message) {
}
```

The response contains:

| Field           | Description                                  |
| --------------- | -------------------------------------------- |
| `success`       | Indicates whether the payment was successful |
| `transactionId` | Generated transaction ID                     |
| `message`       | Payment processing result message            |

### Successful Response

```json
{
    "success": true,
    "transactionId": "TXN-XXXXXXXXXXXX",
    "message": "Payment processed successfully"
}
```

### Failed Response

```json
{
    "success": false,
    "transactionId": null,
    "message": "Payment method not found."
}
```
